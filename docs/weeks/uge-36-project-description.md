# Uge 36 - Project Description

During this course you'll be working on a project throughout the semester. Each lecture introduces a new topic and you'll be applying it to your part of the project.

## Scenario

You'll be working on a real-time enterprise communication platform called Bizcord. It's a Discord-like application that allows users to communicate with each other in real-time. Focus here is only on the backend of the application.

## Scope

- Realtime communication
- Channel management
- User profiles
- Engagement (notifications, reactions, etc.)
- ...

## How will this work?

You'll be working on a subset of the system. Specifically, you'll select a bounded context (functional domain) and work on it. An example could be to work on channel management. In this way you'll continuously be contributing to a microservice throughout the semester.

To experience the full process of developing a microservice, you'll be working on a monorepo. This means that you'll be working on a single repository, but with multiple services. We're going to pretend that this is a "real" project by:

- Using git correctly
- Giving and receiving feedback
- Raising issues

## Rules & Limitations

- You'll be working on a single microservice. You can pick any bounded context you want. Two groups / people can work on the same bounded context. Pick a domain that is interesting to you.
- You'll be contributing to a GitHub repository throughout this course.
- No more than 4 people per team.
